<threat_model>
## Trust Boundaries
| Boundary | Description |
|---|---|
| Admin browser -> configuration API | Setting keys, values, and control actions are untrusted. |
| Configuration API -> SQLite | Typed research controls influence prediction and refresh behavior. |
| SQLite -> KPI read model -> browser | Counts and risk-like metrics must remain server-derived and honestly scoped. |
## STRIDE Threat Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-09 | Tampering | Admin configuration writes | high | mitigate | Allowlisted Pydantic commands, bounded values, Admin policy, and atomic transaction tests. |
| T-02-10 | Elevation of privilege | Admin routes | high | mitigate | Reuse current-user lookup and Admin-only dependency on every read/mutation route. |
| T-02-11 | Information disclosure | KPI response | medium | mitigate | Scope response to Admin and return typed availability/status rather than leaking future-phase data. |
| T-02-12 | Spoofing | research-rule/prototype metadata | medium | mitigate | Server emits centralized label/source metadata; UI renders it without reinterpretation. |
</threat_model>
