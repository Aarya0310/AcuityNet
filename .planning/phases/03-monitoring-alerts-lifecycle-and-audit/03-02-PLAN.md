<threat_model>
| Boundary | Description |
|---|---|
| authenticated command -> lifecycle mutation | Untrusted actor input can request state changes and outcome data. |
| lifecycle/configuration/action -> audit store | Security-relevant evidence crosses into append-only persistence. |
| audit read -> clinical role | Ordered patient evidence is disclosed according to role/resource scope. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03-04 | Elevation of privilege | Lifecycle command routes | high | mitigate | Reuse current-user, patient, and Nurse assignment policy before transition; centralize capability checks. |
| T-03-05 | Tampering | Current state versus event history | high | mitigate | Commit state, AlertEvent, and AuditEvent together; test forced append rollback. |
| T-03-06 | Repudiation | Audit events | high | mitigate | Persist actor, server time, ordered sequence/ID, target, action, outcome, and correlation identifier. |
| T-03-07 | Information disclosure | Denied/audit responses | high | mitigate | Use generic denial responses and safe details only; never persist credentials, bearer tokens, or raw authorization headers. |
| T-03-SC | Tampering | Existing package/runtime dependencies | high | mitigate | Reuse the audited Phase 2 dependency set; no new install is planned. |
</threat_model>
