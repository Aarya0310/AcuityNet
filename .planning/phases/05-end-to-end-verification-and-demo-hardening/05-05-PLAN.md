**Section 1: Prerequisites**

**Section 2: Initial Clone and Dependency Setup**
```
# Clone repository
git clone <repo-url>
cd AcuityNet

# Python backend dependencies
cd backend
python -m venv venv
# Windows: venv\Scripts\activate
# Unix/Mac: source venv/bin/activate
pip install -e .  # Installs from pyproject.toml, including Playwright

# Node frontend dependencies
cd ../frontend
npm install

# Return to root
cd ..
```

**Section 3: Database Initialization (First Time Only)**
```
# Create local SQLite database
cd backend
# On Windows PowerShell:
$env:DATABASE_URL = "sqlite:///$(pwd)\acuitynet.db"
# On Unix/bash:
export DATABASE_URL="sqlite://$(pwd)/acuitynet.db"

# Run migrations (creates schema)
alembic -c alembic.ini upgrade head

# Seed initial fixture data (P-1042 patient, three users, context)
python -c "
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker
from app.seed.demo_data import seed_demo_data

engine = create_engine('$DATABASE_URL')
Sessions = sessionmaker(bind=engine)
with Sessions() as session:
    seed_demo_data(session)
    session.commit()
"
cd ..
```

**Section 6: Demo Walkthrough (Manual Steps)**
```
1. Login as Admin
   - Email: admin@acuitynet
   - Password: admin-password
   - Expected: Admin dashboard with patient list, configuration panel

2. Verify P-1042 is seeded
   - Click P-1042 or search for patient ID
   - Expected: Patient detail page shows bed "ICU-12", initial vitals

3. Advance Vitals (Synthetic Deterioration)
   - Click "Advance Vitals" or equivalent admin control
   - Advance tick 0 → 1 → 2 → 3 → 4
   - Observe: HR increases, SpO2 decreases, RR increases
   - Expected: Vitals change deterministically (same values each time)

4. Check Prediction
   - After tick 3-4, risk should be critical (>threshold)
   - Navigate to Prediction or Clinical Prognosticator panel
   - Expected: Risk score ~0.75+, level "critical", source "deterministic fallback"
   - Verify: "Research Prototype" or "Simulated" label visible

5. Verify Alert Generated
   - Navigate to Alerts page
   - Expected: P-1042 alert appears with priority badge (red for critical)
   - Alert shows: patient, bed, risk score, event, probability

6. Review Historian
   - Click alert → review link or navigate to Historian
   - Expected: Patient demographics, diagnoses, medications, labs, baseline vs contextual risk, rule explanations
   - Verify: "Research Rule" labels, no "validated clinical" language

7. Dispatch Evaluation
   - Doctor logs in (or admin acts as doctor)
   - Navigate to alert detail or dispatch page
   - Click "Evaluate Candidates" or equivalent
   - Expected: Candidate list with Sarah ranked first, scores shown (40% availability, 30% proximity, 20% workload, 10% acuity)
   - Verify: No model_score component (fallback ranking)

8. Confirm Dispatch
   - Admin or Doctor clicks "Confirm Sarah"
   - Expected: Assignment created, alert state → "assigned"
   - Verify: Audit event recorded

9. Nurse Workflow
   - Sarah logs in (email: sarah@acuitynet, password: sarah-password)
   - Expected: Dashboard shows assigned P-1042 alert
   - Click alert → acknowledge
   - Expected: Button state changes, alert state → "acknowledged"
   - Click alert → respond (enter note)
   - Expected: Note persisted, button state changes
   - Click alert → resolve
   - Expected: Alert state → "resolved", assignment completed

10. Verify Audit Trail
    - Admin navigates to audit view or API endpoint
    - Expected: ≥15 ordered events (configuration, advances, alert, dispatch, confirmation, nurse actions)
    - Verify: Events ordered by timestamp, no credential leakage

11. Reset for Next Demo
    - Admin clicks "Reset Database" (if UI available) or runs script
    - Expected: All alerts, assignments, audit artifacts deleted; P-1042 reset to initial state
    - Re-run demo from Step 3
    - Expected: Same vitals progression, same predictions, same workflow (deterministic)
```
